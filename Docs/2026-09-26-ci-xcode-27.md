# 2026-09-26 — CI on Xcode 27

## High-Level Plan

**Problem.** GitHub Actions hadn't shown a green build in years. Since the move to
`runs-on: macos-26-arm64`, every `CI` and `Pull Request Validation` run sat **queued** until
GitHub cancelled it at 24h. `gh run list` shows a long line of runs with status `cancelled`,
mostly `24h0m`. `macos-26-arm64` is not a GitHub-hosted runner label. Its README calls the
image "macOS 26 Arm64", but the labels are `macos-latest`, `macos-26` and `macos-26-xlarge`.
Even on a valid macos-26 label, the image only ships Xcode 26.x, which can't build the project
since #254 moved it to the iOS 27 SDK.

**Solution.** Branch `ci-xcode-27`, PR #256.
- Move every macOS workflow to `runs-on: xcode-27`. That is GitHub's macOS 27 image, still
  labelled "preview" in actions/runner-images#14404; its README is
  `images/macos/xcode-27-arm64-Readme.md`.
- Use `DEVELOPER_DIR=/Applications/Xcode_27.1.app`. That's Xcode 27.1 (27A9269), the same build
  used locally.
- Fix what broke once the jobs actually ran.

**Key changes**
- New reusable `.github/workflows/build-and-test.yml`, called by `ci.yml` (push to
  master/develop, `workflow_dispatch`) and `pr.yml` (pull requests). A PR used to trigger both
  and build twice.
- One app job: build the `iBurn` scheme, which embeds and builds `iBurnWatch`, then test
  `iBurnTests`. The scheme also runs PlayaKitTests and PlayaGeocoderTests. There is no
  `PlayaKitTests` scheme, so the old matrix entry and pr.yml step could never have passed.
- One packages job: `swift test` for PlayaAPI, PlayaColors, PlayaDB, PlayaGeo and PlayaSeed, in
  sequence.
- `deploy.yml`: same image and Xcode; Setup Xcode action dropped. The Fastfile already passes
  `-skipPackagePluginValidation -skipMacroValidation` and has no pod steps.
- App bug found by CI: global search's day and time-of-day filters bucketed event times with the
  device calendar instead of Black Rock City time.

## Failures hit, root causes, fixes

| # | Symptom | Root cause | Fix |
|---|---------|------------|-----|
| 0 | Every run `queued` → `cancelled` after 24h | `macos-26-arm64` isn't a hosted runner label; macos-26 has only Xcode 26 | `runs-on: xcode-27`, `DEVELOPER_DIR=/Applications/Xcode_27.1.app` |
| 1 | (latent) `xcpretty: command not found`, masked | The image has no xcpretty, and the default `bash -e` has no pipefail, so `xcodebuild … \| xcpretty` returned the pipe's last status | `xcbeautify --renderer github-actions` (preinstalled, 3.2.1) plus `defaults.run.shell: bash`, which adds `-o pipefail` |
| 2 | (latent) `PlayaKitTests` scheme doesn't exist | Stale scheme name; its tests live in the `iBurnTests` scheme | Dropped |
| 3 | `BRCSecrets.m: unknown type name 'NSString'` (6×) | The CI stub had no `#import <Foundation/Foundation.h>` and `iBurn-Prefix.pch` is empty. The README template had the same bug. | Added the import to the CI, deploy and README templates |
| 4 | `CopyPlistFile … GoogleService-Info.plist: unable to read input file as a property list` | `touch` made an empty file | Write a valid placeholder plist with fake values in Firebase's formats: API key `A` plus 38 characters, app id `1:<sender>:ios:<hex>`, real bundle id. `BRCAppDelegate` calls `[FIRApp configure]` at launch, which throws on a malformed config inside the test host. |
| 5 | 5-way package matrix plus app job exceeded the account's macOS concurrency, so jobs queued | Free-plan concurrency limit | One packages job loops the five suites and reports every failing package |
| 6 | `GlobalSearchViewModelTests.testTimeOfDayFilterExcludesNonMatchingOccurrences` failed (1 of 699) | **Real bug.** `SearchTimeOfDay.contains(_:calendar:)`, `GlobalSearchFilter.dayBounds` and `dedupedOccurrences` defaulted to `Calendar.current`, but rows show times in `burningManTimeZone`. The runner is on UTC, where the fixture's 12:00 -0700 is 19:00, so "Evening" | Added `Calendar.burningMan` in `iBurn/DateFormatter+iBurn.swift` and used it for bands, day bounds and dedupe. The filter sheet's day labels are formatted in BRC time. `GlobalSearchFilterTests` fixtures use BRC time. New regression test `testBandsAndDayBoundsUseBlackRockCityTimeWhateverTheDeviceZone` pins `NSTimeZone.default` to Asia/Tokyo; verified that it fails (4 assertions) without the fix. |
| 7 | After #6, the job sat 10 min on `Failure collecting diagnostics from simulator: Timed out after 600.0 seconds` | xcodebuild collects a sysdiagnose-like bundle on failure | `-collect-test-diagnostics never`; the xcresult is uploaded on failure |

## Technical Details

### Runner facts (xcode-27 image 20260921.0210.1)
- macOS 27.0 (26A428).
- Xcode 27.0 (27A266a) is the default at `/Applications/Xcode_27.app`.
- Xcode 27.1 (27A9269) is at `/Applications/Xcode_27.1_beta.app`, symlinked as `Xcode_27.1.app`.
  The `_beta` in the path is misleading; the build is the release.
- Xcode 27.2 beta (27B5019j) is also installed.
- Simulator runtimes: iOS 27.0 **only**. Devices include iPhone 17, 17e, 18 Pro, 18 Pro Max and
  Air, plus iPads. watchOS 27.0 has Series 12 and Ultra 4.
- The destination is `platform=iOS Simulator,name=iPhone 18 Pro Max,OS=27.0,arch=arm64`.
  `OS=latest` would resolve to 27.1, the SDK version, and match no device.
- Ruby 3.4.10, Bundler 4.0.21, Fastlane 2.240.1 and xcbeautify 3.2.1 are preinstalled.

### Reproducing the time zone failure locally
`SIMCTL_CHILD_TZ` does *not* reach the XCTest host. `TEST_RUNNER_TZ`, which xcodebuild forwards
to the test runner, does:

```bash
DEST='platform=iOS Simulator,name=iPhone 18 Pro Max,OS=27.0,arch=arm64'
TEST_RUNNER_TZ=UTC xcodebuild test -workspace iBurn.xcworkspace -scheme iBurnTests \
  -destination "$DEST" -skipPackagePluginValidation -skipMacroValidation 2>&1 | xcsift -f toon -w
```

Before the fix: 85 passed, 1 failed (`GlobalSearchViewModelTests.swift:448`). After: 700 passed.

### Timings on the runner
- Package suites: 1.5–2.5 min each as a matrix. Sequential total still finishes before the app
  job.
- App job: about 5 min to build, about 13 min for the test action, including simulator boot.

## Context Preservation
- The `gh run list` history before this work was all `cancelled`: queued runs hit the 24h cap,
  and shorter ones were superseded by concurrency.
- The Crashlytics run-script phase
  (`${BUILD_DIR%/Build/*}/SourcePackages/checkouts/firebase-ios-sdk/Crashlytics/run`) did not
  fail with the placeholder plist in a Debug simulator build.
- The runner runs in UTC, and that is kept on purpose: it's the only place the suite runs
  outside Pacific time.
- Repository secrets present: `CLAUDE_CODE_OAUTH_TOKEN` and `EMBARGO_PASSCODE_SHA256` only.
  `deploy.yml` also expects:
  - `MAPBOX_*`, `CRASHLYTICS_API_TOKEN`, `HOCKEY_*`, `UPDATES_URL`
  - `GOOGLE_SERVICE_INFO_PLIST`
  - `APP_STORE_CONNECT_API_KEY*`
  - `BUILD_CERTIFICATE_BASE64`, `P12_PASSWORD`, `BUILD_PROVISION_PROFILE_BASE64`,
    `KEYCHAIN_PASSWORD`
  - `FASTLANE_*`, `MATCH_PASSWORD`

  None of these are set, so a `v*` tag would fail at signing and upload. CI itself needs no
  secrets.
- The Claude workflows (`claude.yml`, `claude-code-review.yml`) only run on `@claude` comments
  and show as `skipped` otherwise. They're unrelated to Xcode and weren't changed.

## Remaining Work
- `deploy.yml` can't be exercised without a tag and the missing secrets.
  - It doesn't generate the `PlayaDB-<year>.zip` seeds, which are gitignored. A CI-built
    TestFlight build would fall back to on-device JSON import, which works but makes first
    launch slow.
  - Consider running `swift run --package-path Packages/PlayaSeed playa-seed` in deploy before
    fastlane.
- When actions/runner-images promotes the image out of preview or renames the label (for example
  `macos-27`), update `runs-on` in all three workflows.
- Consider branch protection on `master` requiring `Pull Request Validation / Build and Test / *`.
